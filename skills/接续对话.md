# 接续对话 — 跨会话记忆桥接

将任意历史对话的结构化摘要加载到当前上下文中，实现无缝续接。完全利用 QwenPaw 自带的 session 文件体系，不依赖任何第三方工具。

## 触发条件

用户输入「接续对话」时触发。

## 反向过滤

- 用户明确说「不用接」「不用读」时不触发
- 纯聊天、不需要接续上下文时不触发

---

## 标准化指令工作流

### 第一步：列出所有对话

读取 workspace 根目录下的 `chats.json`，解析所有对话。按以下格式展示：

```
1. 对话名 — 通道 — 更新时间
2. 对话名 — 通道 — 更新时间
...
```

### 第二步：等待用户指定

用户输入序号或对话名，如「读第 1 个」或「读那个叫 XXX 的」。

### 第三步：定位精确文件路径

根据 `chats.json` 中的 `channel` 和 `session_id` 定位对应的 session JSON 文件：

- **控制台（default）**：`sessions/console/default_{session_id}.json`
- **控制台（sub）**：`sessions/console/{session_id}_{session_id}.json`
- **QQ/微信**：`sessions/{channel}/` 目录下，文件名包含 `user_id` 的文件

### 第四步：启动子 agent 提炼摘要

用 `spawn_subagent` 启动分身。交给分身的指令必须包含完整的文件结构指引，不给分身任何猜测空间。

**分身指令模板：**

```
## 你的任务

读取指定的 JSON 文件，按下面的规则提取并输出结构化摘要。

## 文件结构（已确认，不需要你自己探索）

文件路径：{精确的 session 文件完整路径}

JSON 结构如下：
  data["agent"]["memory"]["content"]  →  一个列表
    列表里的每个元素又是个列表  →  里面包含若干条消息 dict
      消息 dict 的 key：
        - "role"： "user"（用户） | "assistant"（AI） | "system"（系统）
        - "timestamp"： 时间字符串，如 "2026-06-09 17:09:10.557"
        - "content"： 一个列表，里面是消息内容块

各 role 的 content 格式：
  role = "user"  →  content = [{"type": "text", "text": "用户说的话"}]
    提取：type="text" 的 text 字段

  role = "assistant"  →  content = 可能包含多个块
    如 [{"type": "thinking", "thinking": "..."}, {"type": "text", "text": "回复内容"}, {"type": "tool_use", ...}]
    提取：只取 type="text" 的 text 字段，其他跳过

  role = "system"  →  跳过，不需要处理

## 提取规则

{如果用户指定了时间范围，加这句：只取最近 N 天的消息，按 timestamp 前10位（YYYY-MM-DD）筛选}

1. 遍历 data["agent"]["memory"]["content"] 里的所有消息
2. 只处理 role="user" 和 role="assistant" 的消息
3. 从 content 列表中提取 type="text" 的 text 内容
4. 按 timestamp 排序

## 输出格式

输出以下六项，缺失的填「无」，不要加其他内容：

📋 对话摘要

基本信息：对话名、通道、时间范围、总消息数
主要话题：按讨论占比从高到低排列
关键结论：讨论出的结果、定下的方案
待办事项：还没搞完的、需要后续跟进的
上次聊到哪：对话末尾正在进行的话题
对话文件路径：{精确的 session 文件完整路径}

## 出错处理（重要）

任何步骤遇到以下情况：
- 文件打不开
- 结构跟上面描述的不一样
- 读到的内容不符合预期

→ 立即输出一行：ERROR: 具体描述原因
→ 然后停止，不准重试，不准自己想办法
```

### 分身返回后的处理

**清理分身记录（必须用 Python 脚本，禁止用 edit_file）**

修改 `chats.json` 时，绝对不能用 `edit_file` 做文本替换（容易破坏 JSON 结构导致系统崩溃）。
必须用 Python 脚本：

```python
python3 -c "
import json
path = '/root/.qwenpaw/workspaces/default/chats.json'
with open(path) as f:
    data = json.load(f)
# 过滤掉指定 session_id 的分身记录
data['chats'] = [c for c in data['chats'] if c.get('session_id') != '{sub_session_id}']
with open(path, 'w') as f:
    json.dump(data, f, indent=2)
print('OK')
"
```

删除 session 文件用 `rm`。

**情况 A：分身返回正常摘要**
1. 用 Python 脚本从 `chats.json` 中删除该分身的记录
2. 删除 `sessions/console/sub-xxx.json` 文件
3. 分身不留痕
4. 把摘要加载到当前上下文

**情况 B：分身返回 ERROR**
1. 终止分身
2. 用 Python 脚本清理分身记录和文件
3. **自动重试一次**（用相同指令再派一个分身）
4. 重试成功 → 走情况 A
5. 重试也失败 → 向师兄汇报失败原因，等师兄指示

### 第五步：确认接续

输出：
```
✅ 已接续「{对话名}」—— {时间范围}，共 {消息数} 条消息
```

---

## 质量红线

- 摘要必须包含全部六项，不准缺项
- 不准修改对话原文内容，只提炼不改写
- 分身返回后必须清理记录和文件
- 对话文件路径必须准确，后续能溯源
- **分身失败必须重试一次，不能跳过分身自己上手读**
- **修改 chats.json 必须用 Python 脚本，禁止用 edit_file 做文本替换**

---

## 边缘预案

| 场景 | 处理方式 |
|------|---------|
| 用户指定后找不到对应会话 | 提示用户「没找到，换个名字试试」 |
| session 文件不存在或已损坏 | 去 workspace 根目录下 `dialog/` 找对应日期的 jsonl 归档 |
| 文件过大读不完 | 只读文件末尾部分 + `_compressed_summary` |
| 分身返回 ERROR | 终止→清理→重试一次 |
| 分身重试也失败 | 向师兄汇报，附上 ERROR 原因，等师兄指示 |
| 分身返回格式不符合要求 | 视为失败，按 ERROR 流程处理 |
