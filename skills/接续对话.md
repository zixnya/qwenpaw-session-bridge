# 接续对话 — 跨会话记忆桥接

将任意历史对话的结构化摘要加载到当前上下文中，实现无缝续接。不依赖任何第三方工具，完全利用 QwenPaw 自带的 session 文件体系。

## 触发条件

用户输入「接续对话」时触发。

## 反向过滤

- 用户明确说「不用接」「不用读」时不触发
- 纯聊天、不需要接续上下文时不触发

---

## 标准化指令工作流

### 第一步：列出所有对话

读取 workspace 根目录下的 `chats.json`，解析所有对话。按以下格式展示：

```
1. 对话名 — 通道 — 更新时间
2. 对话名 — 通道 — 更新时间
...
```

### 第二步：等待用户指定

用户输入序号或对话名，如「读第 1 个」或「读那个叫 XXX 的」。

根据 `chats.json` 中的 `channel` 和 `session_id` 定位对应文件。**不需手动拼路径**，直接从 `sessions/{channel}/` 目录下按以下规则查找：
- 列出 `sessions/{channel}/` 下所有 `.json` 文件
- 按修改时间倒序排列
- 根据对话序号或名字匹配

### 第三步：提炼摘要

读取对应的 JSON 文件，提取以下六项结构化摘要。**此步骤不使用子 agent**，直接在当前上下文中操作：

```
📋 对话摘要

基本信息：对话名 | 通道 | 时间范围 | 总消息数
主要话题：按对话轮数占比从高到低排序
关键结论：讨论出的结果、定下的方案
待办事项：还没搞完的、需要后续跟进的
上次聊到哪：对话末尾正在进行的话题
对话文件路径：原始 JSON 文件完整路径
```

分身干完活只把摘要返回给我，分身自行销毁。我只把摘要加载到当前上下文中。

### 第四步：确认接续

输出：
```
✅ 已接续「{对话名}」—— {时间范围}，共 {消息数} 条消息
```

---

## 质量红线

- 摘要必须包含全部六项，不准缺项
- 不准修改对话原文内容，只提炼不改写
- 分身销毁前必须返回摘要，不能空跑
- 对话文件路径必须准确，后续能溯源

---

## 边缘预案

| 场景 | 处理方式 |
|------|---------|
| 用户指定后找不到对应会话 | 提示用户「没找到，换个名字试试」 |
| session 文件不存在或已损坏 | 去 workspace 根目录下 `dialog/` 找对应日期的 jsonl 归档 |
| 文件过大读不完 | 只读文件末尾部分 + `_compressed_summary` |
