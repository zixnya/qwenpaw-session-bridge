# 接续对话 — 跨会话记忆桥接

将任意历史对话的结构化摘要加载到当前上下文中，实现无缝续接。不依赖任何第三方工具，完全利用 QwenPaw 自带的 session 文件体系。

## 触发条件

用户输入「接续对话」时触发。

## 反向过滤

- 用户明确说「不用接」「不用读」时不触发
- 纯聊天、不需要接续上下文时不触发

---

## 标准化指令工作流

### 第一步：列出所有对话

读取 workspace 根目录下的 `chats.json`，解析所有对话。按以下格式展示：

```
1. 对话名 — 通道 — 更新时间
2. 对话名 — 通道 — 更新时间
...
```

### 第二步：等待用户指定

用户输入序号或对话名，如「读第 1 个」或「读那个叫 XXX 的」。

从 `sessions/{channel}/` 下列出所有 `.json` 文件，按修改时间倒序排列。根据对话序号或 `chats.json` 中的 `name` 匹配 — **不用 session_id 拼文件名，直接从目录里找**。

### 第三步：启动子 agent 提炼摘要

用 `spawn_subagent` 启动一个分身。**任务指令必须严格按以下模板，不准自由发挥：**

> 你的任务只有一个：读取指定 JSON 文件 `{完整路径}`，提取六项信息输出。**不准做其他任何事情，不准聊天，不准分析，不准建议，不准输出多余内容。**
>
> 读取后输出以下格式（直接输出，不要加任何额外文字）：
> 📋 对话摘要
> 基本信息：对话名 | 通道 | 时间范围 | 总消息数
> 主要话题：按对话轮数占比排序
> 关键结论：
> 待办事项：
> 上次聊到哪：
> 对话文件路径：{完整路径}

如果分身返回的内容不符合此格式，视为失败，终止重试。

分身干完活只把摘要返回给我，然后：
1. 从 `chats.json` 中删除该分身的记录
2. 删除 `sessions/console/sub-xxx.json` 文件
3. 分身不留痕，列表干净

### 第四步：确认接续

输出：
```
✅ 已接续「{对话名}」—— {时间范围}，共 {消息数} 条消息
```

---

## 质量红线

- 摘要必须包含全部六项，不准缺项
- 不准修改对话原文内容，只提炼不改写
- 分身销毁前必须返回摘要，不能空跑
- 对话文件路径必须准确，后续能溯源

---

## 边缘预案

| 场景 | 处理方式 |
|------|---------|
| 用户指定后找不到对应会话 | 提示用户「没找到，换个名字试试」 |
| session 文件不存在或已损坏 | 去 workspace 根目录下 `dialog/` 找对应日期的 jsonl 归档 |
| 文件过大读不完 | 只读文件末尾部分 + `_compressed_summary` |
| 分身跑偏或自言自语 | 终止分身，重试一次，任务指令中强调「只准读取文件输出摘要」 |
